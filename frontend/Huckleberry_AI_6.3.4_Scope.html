ABOUT THIS BUILD

What changed from Huckleberry 5.0 → 6.0

6.1 additions — PDF viewer, tools, bug fixes

6.0 proved the pipeline shape. The first real-PDF run (Wendy's from the TracePoint corpus) detected 14,151,546 sqft against a 1,565 sqft answer — three orders of magnitude wrong. Root cause analysis pointed at four compounding failures: Stage 1 couldn't find scale text, Stage 2 didn't know where the detail views were, Stage 6 was using the cluster bounding box as the polygon, and Stage 7 fell through all five tiers to the scoring formula (which optimizes for proximity to 3,000 sqft — a weak prior).

6.1 adds the tools needed to address three of the four. The fourth (Stage 6 bbox-as-polygon) is sidestepped: the user draws the polygon with the polygon tool and it overrides Stage 12's winner. The VIEWER & TOOLS tab is an OpenSeadragon tiled-zoom viewer with a Konva annotation layer on top. Seven tools all store geometry in PDF points:

  • Calibrate — click two ends of a known dimension, enter its real length (accepts 100, 100', 100'-6"). Sets manual scale override, feeds Tier 0 of Stage 7.
  • Measure — click two points, shows distance at current scale.
  • Polygon — click each corner, double-click to close. The pipeline replaces Stage 12's winner with the user polygon and recomputes area via shoelace. This is the L-shape / T-shape fix.
  • Rectangle — drag to draw a rectangular building outline.
  • Exclude Zone — drag to mark a detail view or notes area. These zones get merged into page.zones before Stage 2 runs, addressing bug #2.
  • Pan / Zoom / Delete — standard viewer controls.

The dashed-line detection bug (bug #3) was a missing PDF graphics-state stack. The original extractor tracked setLineWidth and setDash as global state, so state changes made inside a q / Q (save/restore) block leaked across subsequent paths or never registered at all. 6.1 tracks the full q / Q stack, so each path inherits its correct stroke width and dash flag at the moment of construction. A new integration test (fix · dash filter: dashed-heavy paths get dropped (bug #3)) exercises this directly.

16 new unit tests and 1 new integration test ship with 6.1, bringing the total to 53 tests, all green. The critical ones are tool · polygonAreaPt: L-shape → 4,100 sqft and tool · end-to-end: L-shape polygon → correct sqft (bbox would be wrong) — these prove that when the user draws a correct L-shape, the pipeline emits 4,100 sqft on a 100×50-with-30×30-bite building, not the 5,000 sqft bbox answer. That's the Wendy's-class fix demonstrated with math.

What 6.1 still can't do: automatic detection on a Wendy's-class plan. If you drop a real PDF and hit RUN without visiting the VIEWER tab to calibrate and/or draw the outline, you will still get garbage. The viewer + tools are the handrails that make the automatic pipeline's failures recoverable by a human in about 30 seconds of clicking. That's the actual product.

The Surgery

Huckleberry 5.0 ran a four-pass Claude pipeline: CLASSIFY (Haiku) → SURVEY (Sonnet vision) → EXTRACT (Sonnet text) → VALIDATE (Haiku). Every plan cost $0.15–$0.25 and depended on the Anthropic API being reachable. Huckleberry 6.0 strips that entire stack out.

Removed: claude_pipeline.py, plan_analyzer.py (AI portions), trap_filter.py, prompts/, every SURVEY/EXTRACT/VALIDATE code path, the API-key bar, the token-usage panel, the cost tracker, and every dependency on ANTHROPIC_API_KEY.

Bolted in: the TracePoint AI 12-stage geometry engine described in the April 2026 technical report — dispatch-gate plan-set intelligence, four composable filter gates, union-find clustering at 0.5-inch proximity, five-tier scale determination, and the post-clustering scoring trio (interior density, rectilinear, confidence-gap).

The 12 Stages

  • 1. Dispatch Gate — runs once per plan set; produces a PlanSetContext (page classification, cross-refs, legends, zones)
  • 2. Zone Mask — drops paths inside detail views and title blocks
  • 3. Weight Filter — keeps only paths with stroke width > 1.0 pt
  • 4. Length Filter — drops paths shorter than 0.5 inches
  • 5. Dash Filter — drops dashed and dotted paths
  • 6. Union-Find Clustering — merges paths within 0.5" proximity; minimum 50 in² output
  • 7. Scale Determination — five tiers: manual → dispatch → text label → dimension cross-check → multi-page → scoring formula
  • 8. Perimeter Cleanup — exterior ring simplification
  • 9. Confidence Score — gap between best and second-best candidate
  • 10. Interior Density Score — callout density bonus (threshold 0.06), long-text ratio penalty (threshold 0.5), noise-zone overlap
  • 11. Rectilinear Score — fraction of paths that are horizontal or vertical
  • 12. Final Polygon Selection — combines scoring factors and emits the winning polygon

Karpathy Discipline

Karpathy's rule for AI system development is brutally simple: build a thing, then test it, then test it again, then test it a third time before you trust it. Every stage in this pipeline ships with at least one unit test against synthetic ground-truth. The integration tests then run the full pipe end-to-end against a synthetic 5,000 sqft building polygon and assert that the detected area is within tolerance. The Tests tab lets you re-run the whole battery any time.

What's the same

The Huckleberry visual identity is preserved: Rajdhani display, Outfit body, JetBrains Mono numbers, the dark cyan-on-charcoal theme, the boxed status bar, the 12-stage sidebar pulse. If you used Huckleberry 5.0 you'll find your way around 6.0 in about ten seconds.

What this is and what it isn't

What this is: a single-file, fully-offline reference implementation of the TracePoint pipeline architecture, with a complete test harness, designed for verification and comparison against the production system.

What this isn't: a full reimplementation of every TracePoint diagnostic and edge-case (the symbol diagnostic, the hatching diagnostic, the architect-profile flywheel are scoped for production builds). The pipeline shape, gate composability, and scoring math are faithful; the depth of plan-set intelligence is intentionally trimmed to fit a browser.
