ABOUT THIS BUILD

Phase 2 architecture — what changed in the strip-and-connect

Phase 2 architecture

phase2.v1.0.0 is the API-connected viewer that succeeds Huckleberry v6.3.5. The 12-stage TracePoint geometry pipeline, ROOF_VOCAB scope extractor, and PDF.js path/text walker have all moved server-side. The browser now does what browsers should do: render PDF pages, drive an OpenSeadragon + Konva annotation surface, and export takeoff Excel files. Everything else flows from the backend API.

What strips: the entire TP namespace (12-stage pipeline JS port), ROOF_VOCAB + extractScope + classifyPage (scope inference), the PDF.js operator-list walker (path/text extraction), buildSyntheticPlan + the synthetic plan generator, the Pipeline tab and its visualizer canvas, plus the 142 tests that exercised this stripped code (UNIT_TESTS pipeline-side, INTEGRATION_TESTS, SCOPE_TESTS, SCOPE_INTEGRATION_TESTS, plus 4 pipeline-dependent TOOL_TESTS). Net: ~4,150 lines deleted from v6.3.5.

What stays: the OpenSeadragon viewer + Konva annotation overlay, all annotation tools (calibrate / measure / line / polygon / rectangle / pin / excludeZone), takeoff Excel export via the xlsx CDN library, and the v6.3 seed-item table (membrane / insulation / cover board / drains / scuppers / RTUs / corners / coping / edge-metal / cricket / etc.). The 11 surviving TOOL_TESTS test what's left.

What's new: the apiClient wrapper hits http://127.0.0.1:8000 by default. Only healthCheck() is wired in E.2.1 — createJob / getJob / listJobs / getResults / dispatchJob are stubs throwing not_implemented_in_e2_1 until E.2.2 ships. The 3-state status bar (CHECKING / CONNECTED / UNREACHABLE) polls /health every 30 seconds; replaces v6.3.5's static "AI BACKEND: REMOVED" copy.

The architectural reframing: planSet is no longer the application's data model. It's a page-rendering cache. The application's data model is the API-provided job state — that lands in E.2.2 when scope + pages render from GET /jobs/{id}/results.

The 12 stages (now backend)

For reference. These run server-side in backend/core/dispatch_gate.py + backend/core/geometry/* + backend/core/scoring/*.

  • 1. Dispatch Gate — page classification, cross-refs, legends, zones
  • 2. Zone Mask — drops paths inside detail views and title blocks
  • 3. Weight Filter — keeps only heavy paths
  • 4. Length Filter — drops paths shorter than 0.5 inches
  • 5. Dash Filter — drops dashed and dotted paths
  • 6. Union-Find Clustering — merges paths within 0.5"
  • 7. Scale Determination — five-tier scale picker
  • 8. Perimeter Cleanup — exterior ring simplification
  • 9. Confidence Score — gap between best and second-best candidate
  • 10. Interior Density Score — callout density bonus
  • 11. Rectilinear Score — fraction of horizontal/vertical paths
  • 12. Final Polygon Selection — winning polygon

Karpathy discipline

"Build a thing, then test it, then test it again, then test it a third time" — applied to the strip itself. v6.3.5's 138/138 floor verified pre-strip; phase2.v1.0.0's 20/20 floor verified post-strip. Every retiring test had its coverage relocated (most to backend's 222-test suite; a few ported with hardcoded fixtures).
