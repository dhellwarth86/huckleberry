## Discipline lessons from THIS session that future-Claude should not have to re-learn

These are session-derived. The cost of each was real (hours of conversation). Internalize them so the next session doesn't pay the cost again.

**1. Read primary sources before architecting.** The architectural-gap finding (v0.2 ports Layer 3 only, Stages 2–12 missing) was sitting in the TracePoint paper the entire time. I missed it across multiple sessions because I was reasoning about TracePoint from memory rather than reading the paper end-to-end. Daniel re-read it and found the gap in one session. Lesson: when working with TracePoint-derived code or architecture, read the paper first, every time.

**2. Diagnostic results have to be interpreted in the right architectural frame.** The intake diagnostic Pass 1 surfaced an "asymmetry" (10/15 STACK had positive manufacturer evidence with empty scope_pages) that LOOKED actionable. Pass 2 contextualized it (29 of 35 hits were sealants/drywall/etc., not roofing context). The asymmetry largely dissolved. Without Pass 2, march orders for the wrong thing would have been written. Lesson: when data points toward action, run the cheap follow-up before committing to the action. Always.

**3. Drift toward "roofing only" is the failure mode to refuse.** Multiple sessions (including mine) framed Huckleberry as a roofing program with extensions. TracePoint paper §2.1 is explicit that Layers 1–3 are trade-agnostic and that trade modules are pluggable. The disabled glazing/siding cards in the frontend say so. The seed files glazing_assemblies.py and glazing_materials.py (no consumer) say so. Daniel's repeated insistence in this conversation says so. Refusing the drift requires active discipline.

**4. Confidence theater is real and has to be refused.** The Grok-produced schema document claimed "fully validated against Sanibel Fire Station 172" with quality scores like 0.97 and labels like "Production Ready." Grok had no access to the Sanibel PDF. The validation was fabricated. Lesson: a measurement without a named evaluation set is not a measurement. If you encounter similar inputs, refuse them.

**5. The TracePoint folder copy pattern is the right approach.** Reading TracePoint from a network drive (v0.2 used `C:/TracePoint/`) and reading TracePoint from a folder placed in the project tree (B.1+ uses `tracepoint_port/TracePoint/`) are functionally identical. Both treat the folder as read-only authoritative source. The pattern is proven. Don't second-guess it.

**6. Karpathy applies to discussions, not just code.** Daniel said "Karpathy logic" multiple times this session when discipline was slipping. The signal works: stop, re-read CLAUDE.md, re-read the relevant authoritative documents, restart from a measured position. When you find yourself proposing architecture from memory or from pattern-matching prior projects, pause and read the canon.

**7. Two passes of read-only diagnostic produce more leverage than one pass of speculation patching.** Pass 1 surfaced an asymmetry. Pass 2 dissolved most of it. Together they cost ~15 minutes of Claude Code time and produced architectural clarity. The same time spent guessing at fixes would have produced regressions and re-work.

**8. Honest non-conclusions are a discipline tool.** Every diagnostic and observation document records what it cannot conclude as well as what it can. Sample size limits, ground-truth absence, corpus characteristics. The discipline of explicit non-conclusions is what kept the v0.2 validation honest. The same discipline keeps Pass 1, Pass 2, and the public corpus observations honest. Carry it forward.
